# neco-formsum

[English](README.md)

`neco-formsum` は、正規化した冪根の単項式の有理係数和 ( 形式和 ) を厳密に扱う crate です。計算の途中の値は記号のまま保持し、値の等しさは疎な正規形の構造を照合して判定します。符号の判定には、厳密値を含むことを証明した二進有理数の区間を使います。

## 入力と正規形

構成用の入力と正規形の役割は、型と操作ごとに分かれています。

- `RawTerm`: 約分する前の有理係数と、構成用の単項式
- `RawFormSum::normalize`: すべての入力を検証して正規化する
- `FormSum`: 辞書順に並んだ相異なる基底と、零でない係数を持つ正規形

正規化では、単項式の有理数の因子を係数へ移し、同じ `RadicalBasis` を持つ項をまとめ、係数が零になった項を取り除きます。正規化の後に項が一つも残らない形式和は、零を表します。たとえば次の値は、基底 $ 1, 2^{1/2}, 3^{1/2} $ に対する係数が $ 1, 2, -1 $ である、三つの項からなる正規形です。

$$ 1 + 2\sqrt{2} - \sqrt{3} $$

正規化の結果は、入力の順序によらず同じです。入力に、分母が零の係数や指数、`0^0`、零の負冪が含まれる場合は、それらの失敗を重複を除いて昇順に並べた `NormalizationErrors<FormSumErrorKind>` が返ります。演算を続けられない失敗が起きた場合は、その場で処理を止め、一件の失敗として返します。

## 厳密演算

形式和は、加算、減算、乗算、除算と逆元の計算を提供し、どの結果も正規形で返します。除算と逆元の計算では、有限な冪根拡大の上で、有理数を係数とする厳密な連立一次方程式を解きます。
零で割った場合は、`FormSumErrorKind::DivisionByZero` を返します。

```rust
use neco_formsum::FormSum;

fn main() -> Result<(), neco_formsum::FormSumErrorKind> {
    let one = FormSum::one()?;
    let two = one.add(&one)?;
    let quotient = two.div(&one)?;

    assert_eq!(quotient, two);
    assert!(FormSum::zero().is_zero());
    Ok(())
}
```

## 有限な冪根拡大

`extension_with` は、二つの値をともに含む最小の共通の拡大を構成します。たとえば $ \sqrt{2} $ と $ \sqrt{3} $ を含む最小の拡大は $ \mathbb{Q}(\sqrt{2}, \sqrt{3}) $ で、次元 $ D = 4 $ の基底を持ちます。
`RadicalExtension` は、昇順の素数の列、指数の分母の列、基底の数を公開します。基底の並びは、最後の座標が最も速く変わる混合基数 ( mixed-radix ) の順です。
座標による表現は、形式和の値を、この基底に対する有理数の係数の列として扱うためのものです。

- `coordinates_with`: 必要な素数と分母を含む拡大の上で、値を座標で表す
- `RadicalCoordinates`: 形式和への復元と、列優先の乗算行列の生成を行う

行列の添字は次の式で求めます。

```text
row + D * column
```

この要素は、列で指定した基底元を値に掛けた結果について、行で指定した基底元の係数を表します。

`annihilating_coefficients` は、整数係数の原始的な零化多項式を返します。係数は次数の低い順に並び、最高次の係数は正です。

## 区間と符号

- `enclose(bits)`: 厳密値を含み、幅が `2^-bits` 以下の区間を返す
- `sign`: まず正規形の項の列が空 ( 値が零 ) かを確かめ、零でなければ、零を含まない区間から符号を得る

冪根の区間は、整数冪の不等式だけを根拠に構成します。

## 失敗とメモリ確保

失敗に関わる公開型は、失敗の種類と、次元の超過が起きた対象を表します。

- `FormSumErrorKind`: 下位 crate の失敗、零除算、次元の超過、確保の拒否
- `DimensionResource`: 次元の超過が起きた対象 ( 指数の分母、基底の数、行列の要素数 ) を区別する

可変長の格納領域を所有する型は `try_clone` を提供し、複製時のメモリ確保の失敗を `Result` で受け取れます。

## 機能と依存

既定の `std` 機能を有効にすると、`FormSumErrorKind` を標準のエラー型として使えます。
この機能は、依存する二つの crate の同名の機能も有効にします。
既定機能を無効にすると、同じ値と同じ失敗を扱う `core + alloc` の構成になります。

```console
cargo check -p neco-formsum --no-default-features
```

実行時には、`neco-bigint` と `neco-monomial` に依存します。
