# neco-linear-types

[English](README.md)

`neco-linear-types` は、数値線形代数で使う、検査付きの形状、検証済みのベクトル、線形作用素のインターフェースを公開型として提供します。

## 公開 API

- `Shape`: 行数と列数を保持し、行数×列数が `usize` に収まるかを検査する
- `RowIndex`, `ColumnIndex`: 形状の検証を通して生成する添字
- `Vector<T>`: 値を所有し、長さ、個々の要素、全要素を読み出せるベクトル
- `LinearOperator<T>`: 入力の長さ、出力の長さ、作用を定める線形作用素のインターフェース
- `LinearError`: 次元、添字、格納長、容量の超過、メモリ確保、不正な格納の失敗

`LinearOperator<T>` では、`domain` が入力の長さを返します。
`codomain` は出力の長さを返し、`apply` は入力のベクトルに作用素を適用します。

```text
domain(&self) -> usize
codomain(&self) -> usize
apply(&self, input: &Vector<T>) -> Result<Vector<T>, LinearError>
```

入力と出力の長さは、各実装が検査します。

`LinearError` の容量の超過 ( `CapacityOverflow` ) は、個数、添字、確保する領域のバイト数の計算が上限を超えた場合の失敗です。

不正な格納の失敗は、格納領域の長さが `isize::MAX` を超える場合と、CSR の不変条件に反する場合に返ります。
構築済みの行列から要素を読み出す時に、格納領域が宣言した形状より短いと分かった場合も、同じ失敗になります。
また、`neco-linear-exact` の消去法では、作業用の行列、右辺、解、核の基底ベクトルの格納領域が宣言した次元より短い場合と、ピボットの位置や数が行列の次元を超えた場合に、この失敗を返します。

格納長の失敗 ( `StorageLengthMismatch` ) は、渡した要素の並びやベクトルの長さが、求められる長さと異なる場合の失敗です。
求められる長さは、密行列の構築では形状の要素数 ( 行数×列数 ) 、作用素の適用では作用素の入力の長さ ( `domain` の値 ) 、連立一次方程式の求解では係数行列の行数です。

## ランタイム構成

既定では標準ライブラリを使います。既定機能を無効にすると、動的メモリ確保だけを前提とする `core + alloc` の構成になります。
