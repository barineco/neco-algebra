# 代数演算における観測形式

この文書は、生成器が書き出す観測バッチと、検査器が返す検査結果の形式を定めます。また、演算族ごとに、Lean の検査器が確かめる性質を示します。観測バッチの値は検査を通るまで未検証の観測であり、判定は検査結果にだけ記録します。
Lean の検査器は、Rust の生成器のコードを使わずに、入力と観測値から演算族ごとの条件を計算し直します。以下、この検査を独立検査と呼びます。

## 共通規約

観測バッチは正規形の JSON ( canonical JSON ) のオブジェクトで、次の規約に従います。

- 文書: UTF-8 のオブジェクト
- 形式識別子: `schema`
- 観測の一覧: `cases`
- 観測識別子: `caseId`
- 演算族: `operation`
- 入力: `input`
- 観測値: `observation`
- 観測識別子の制約: バッチの中で空でなく、一意である
- 項目名の順序: Unicode の符号位置の順
- トークン間の空白文字: なし
- 復号: 重複した項目名を拒否する
- 再符号化: 再符号化したバイト列が、入力のバイト列と一致する
- ダイジェスト: 確定したバイト列に対する SHA-256
- 整数: 正規形の十進数の文字列
- 二進有理数 ( dyadic rational ): 整数と指数
- 浮動小数点値: 小文字の 16 進数で 16 桁
- 有理数: 分子と正の分母

有理数の成功値と線形演算の係数は、正の分母だけを受理します。有理数の既約化に渡す分母は非負です。分母の零は、零分母の失敗を観測する入力として受理します。負数と先頭の 0 は、形式の不整合として拒否します。既約性と分母の正規化は、独立検査で確かめます。

成功の観測は値を持ち、失敗の観測は失敗の種別を持ちます。失敗の種別は、生成器が公開 API の結果から決めて記録したものです。独立検査では、入力から失敗の種別を再計算し、記録された種別と一致するかを確かめます。成功値と失敗の種別は、一つの観測の中で排他的です。

観測を作れない場合、生成器は観測バッチの代わりに標準エラーへ JSON を出力し、終了コード 1 で終わります。この JSON の `adapterFailure` が原因を示します。生成要求は、作る観測を、成功か、失敗の種別の一つで指定します。作った観測がこの指定と異なる場合は `unexpectedPublicApiOutcome` です。

演算族は、観測ごとに `operation` に記録します。形式識別子は、バッチごとに `schema` に一度だけ記録します。

初版の形式識別子は `neco.algebra.observation-batch.v1` です。前半の `neco.algebra` が検証の対象のリポジトリを表し、後半が観測バッチの形式とその版を表します。

## 初版の演算族

### 有理数の既約化

- 入力: 分子と分母
- 成功の観測: 既約な分子と正の分母
- 失敗の観測: 零分母
- Lean による再計算: 分母が零でないこと、符号の正規化、最大公約数による既約性、入力と成功値が等しいこと

### 拡張ユークリッド互除法

- 入力: 二つの整数
- 成功の観測: 最大公約数と二つの係数
- Lean による再計算: 最大公約数が非負で両方の整数を割り切ること、係数による等式

### 代数的数の根の分離

- 入力: 整数係数の定義多項式
- 成功の観測: 一つの実根を含む二進有理数の分離区間
- 失敗の観測: 分離できる実根が無い
- Lean による再計算: 端点で多項式が零でないこと、両端点で符号が反転すること、分離区間の上で、導関数の値の範囲が零を含まないこと

### 浮動小数点への射影

- 入力: 二進有理数と精度
- 成功の観測: 浮動小数点値のビット列、二つの端点、絶対誤差
- 失敗の観測: 非有限値
- Lean による再計算: 二進有理数の正確な値、区間による包含、区間の幅、両端までの距離の最大値

### 有理数の連立一次方程式の一意解

- 入力: 正規形の有理数の行列と右辺
- 成功の観測: 係数行列が正方で階数が列数に等しい系の、正規形の有理数の解
- 失敗の観測: 次元の不一致 ( 右辺の長さが行数と異なる系 )、特異な系 ( 係数行列が正方で階数が列数未満の系 )
- Lean による再計算: 係数の既約性と分母の正規化、形状、行列方程式、一意性

### 有理数の連立一次方程式のアフィン解

- 入力: 正規形の有理数の行列と右辺
- 成功の観測: 行数が列数より少なく階数が行数に等しい系の、正規形の有理数の特解と基底
- 失敗の観測: 次元の不一致 ( 右辺の長さが行数と異なる系 )、特異な系 ( 係数行列が正方で階数が列数未満の系 )
- Lean による再計算: 係数の既約性と分母の正規化、形状、特解の行列方程式、核の条件、基底の一次独立性

二つの演算族では、生成器は、係数行列の形状と階数に `ExactMatrix::solve` の結果を合わせて、観測を決めます。右辺の長さが行数と異なる系の観測は、係数行列によらず次元の不一致です。観測を作れない場合の `adapterFailure` は、原因によって分かれます。

- 系が上の観測のどれにも当たらない: `unexpectedPublicApiOutcome`
- 係数行列の階数の計算が失敗した: `publicApiConstructionFailure`

## 判定

- `verified`: 独立検査と観測が一致し、確認できた
- `refuted`: 検査できる矛盾があり、反証された
- `undetermined`: 初版の範囲外の観測、または決定できない観測
- `invalid`: 正規形でないバイト列、形式の不整合、観測識別子の不整合

## 観測器による結果の照合

観測器は、呼び出し側が保存した観測バッチと検査器の結果を照合するコマンドです。

```sh
neco-algebra-observer --batch observation-batch.json --checker-result checker-result.json
```

観測器は、保存済みの二つのファイルのバイト列だけを入力にします。
配置済みの成果物を使う実行方法は、`artifacts/README.md` にあります。

観測の一覧 ( `cases` ) を復号できたバッチには、一件以上の観測と、一意で空でない識別子が必要です。検査結果は正規形の JSON で、元のバイト列の SHA-256 と、バッチと同じ数で同じ順序の識別子を持ち、各観測の判定が定義された四つの判定のいずれかである必要があります。観測器は照合した判定の件数を返し、検査器が下した数学的な判定はそのまま保持します。

### 正常な結果と復号できない入力

成功時は終了コード 0 で終わり、標準出力に、次の形式の正規形の JSON と末尾の改行を出力します。

```text
cases: 渡された検査結果に含まれる判定ごとの件数
digest: バッチの実際のバイト列に対する SHA-256
```

件数の辞書には、結果に含まれる判定だけが現れます。標準エラーは空です。

入力の復号に失敗した場合、検査器は識別子が空の invalid の結果を一件だけ返します。観測器はこの結果を、元のバイト列のハッシュと、`cases` が `{"caseId":"","verdict":"invalid"}` の一件だけであることで識別して受理します。識別子が空の invalid の結果を、観測の一覧を復号できたバッチの結果として渡した入力は拒否します。

### 不成立と読み取りの失敗

拒否した場合は終了コード 2 で終わり、標準エラーへ一つの正規形の JSON と末尾の改行を出力します。結果の照合を拒否した場合、標準出力は空です。
標準エラーの JSON は、形式識別子、失敗の分類、処理の失敗の件数と一覧、失敗の内容を項目に持ちます。下のブロックの各行は、項目の名前と値の組です。

```text
schema: neco.algebra.observer-failure.v1
classification: failure.kind
processErrorCount: 形式または呼び出しの誤りでは 0、processFailure では 1
processErrors: [] または [failure]
failure: { kind, failingOperation, violatedCondition,
           operandProvenance, witness, contributingFailures }
```

検査結果が不正な場合の分類と失敗した操作は、結果が違反した条件によって決まります。

| 結果の変更 | classification | failingOperation |
|---|---|---|
| 入力と異なるハッシュ | resultDigestMismatch | reconcile |
| 識別子の順序の変更 | caseCorrespondenceMismatch | reconcile |
| 観測の一覧を空にした結果 | resultInvalid | decodeCheckerResult |
| 定義されていない判定 | resultInvalid | decodeCheckerResult |

失敗の内容の `violatedCondition` には、条件ごとに定まった識別文字列が入ります。

```text
digest: checker digest differs from actual input bytes
order: caseId order differs
empty: result cases must be nonempty
verdict: unknown verdict
```

ファイルの読み取りに失敗した場合は、失敗した操作の名前と、二つの入力ファイルのパスを記録します。読み取りの失敗と引数の不整合の分類は、検査結果の形式による拒否の分類とは別です。

| 不成立 | classification | failingOperation | processErrorCount |
|---|---|---|---:|
| バッチの読み取り失敗 | processFailure | readBatch | 1 |
| 結果の読み取り失敗 | processFailure | readCheckerResult | 1 |
| 引数の不整合 | invalidProcessInvocation | parseCli | 0 |
